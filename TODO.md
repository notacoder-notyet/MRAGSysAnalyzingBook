### 🔴 ГЛАВНЫЙ ВЫВОД eval (06.10.2026)

**Провалы retrieval вызваны не эмбеддингами, а парсингом таблиц/схем.**
Все 20 провальных вопросов (100%) указывают на страницы с «мусорным» текстом
(средняя мусорность 0.291 против 0.200 у успехов; у страницы 1:5 — 0.91).
pdfplumber читает таблицы и схемы по колонкам, превращая их в бессмысленный
набор символов (`Н И а м п е р е а т в д л л е и н н`), и такие страницы
получают бесполезные эмбеддинги.

Приоритет исправлений пересмотрен по фактам:

| Приоритет | Задача | Почему |
|-----------|--------|--------|
| 🔴 High | **Парсинг таблиц/схем** (Camelot / pdfplumber table settings / OpenCV) | Блокирует 100% провалов |
| 🟡 Medium | Разрешить **несколько refs** на вопрос в gold-наборе | Часть «провалов» — верные соседние страницы (напр. 23:1 вместо 23:2) |
| 🟡 Medium | Upgrade эмбеддингов → `BAAI/bge-m3` | Поможет, но не решает мусорный текст |
| 🟢 Low | Reranker (cross-encoder) | Точность на top-k, не recall |

Метрика для контроля прогресса: `python retrieval_report.py` — смотреть, как
падает доля провалов с мусорным текстом.

## 📝 Заметки по архитектуре

**VectorStore интерфейс:**
```python
class VectorStore(ABC):
    @abstractmethod
    def add(embeddings, metadatas, ids): ...
    @abstractmethod
    def search(query_vector, top_k, filter_dict=None): ...
    @abstractmethod
    def delete(ids): ...
    @abstractmethod
    def count(): ...
```

**Конфиг (env / yaml):**
```yaml
vector_store:
  type: "chroma"  # или "qdrant"
  chroma:
    persist_dir: "./data/chroma"
    collection: "lessons"
  qdrant:
    url: "http://localhost:6333"
    collection: "lessons"
```

**Переключение одной строчкой в коде / конфиге.**
